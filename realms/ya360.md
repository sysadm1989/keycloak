# Реалм `ya360` — SSO в Yandex 360

Keycloak здесь **IdP**, Yandex 360 — **SP** (SAML). OIDC для 360 не используется.

## 1. Импорт реалма

```bash
cp realms/ya360.yml.example realms/ya360.yml
ansible-playbook playbooks/realms.yml --ask-vault-pass
```

Нужен образ с темой `nemero-ad`. LDAP для ya360 появится, если добавить элемент в `keycloak_ldap_federations` с `realm: ya360`.

## 2. Админ только реалма ya360 (рекомендуется из master)

Когда создаётся реалм `ya360`, в **master** появляется клиент **`ya360-realm`** с ролями управления только этим реалмом. Учётку заводите в **master** — AD в ya360 ей не мешает (разные реалмы).

**Не** выдавайте глобальную роль master `admin`.

### Создание

1. Войти как master-admin: `https://sso.nemero.online/admin/`
2. Реалм **master** → **Users → Create user**  
   - Username: например `ya360-operator`
   - Enabled / Email verified: On
3. **Credentials → Set password**, Temporary: Off
4. **Role mapping → Assign role → Filter by clients → `ya360-realm`**
   - обязательно: **`query-realms`** (видеть реалм в списке)
   - настройки реалма: **`manage-realm`** (+ обычно `view-realm`)
   - пользователи: `manage-users`, `view-users`, `query-users`
   - клиенты (SAML Yandex 360): `manage-clients`, `view-clients`, `query-clients`
   - «почти полный» доступ к ya360 без master-admin: все роли клиента `ya360-realm`, **кроме** если не хотите impersonation и т.п.
5. Выйти.

Вход оператора:

```text
https://sso.nemero.online/admin/
```

Логин: `ya360-operator` (реалм master). В консоли доступен только **ya360** (и то, что дали ролями). GitLab/master чужие реалмы не управляются.

Проверка: под этим пользователем не должно быть прав менять `platforms` или пользователей master.

### Вариант B — учётка внутри ya360

Если нужен вход в dedicated console `https://sso.nemero.online/admin/ya360/console/`:

1. Реалм **ya360** → Create user (`local-ya360-admin`, имя без коллизии с будущим AD)
2. Roles → client **`realm-management`** → `manage-realm` (+ `manage-users` / `manage-clients` по необходимости)

Локальные и AD-пользователи в ya360 сосуществуют; конфликт только при одинаковом username.

## 3. Пользователи для входа в Yandex 360

Пока без AD — создайте пользователей в реалме ya360 (Users):

- Username / Email — email домена организации в Yandex 360 (тот же домен, что в 360)
- First name, Last name — обязательны для SAML-атрибутов
- Password + Email verified

Позже LDAP AD/FreeIPA — элемент в `keycloak_ldap_federations` с `realm: ya360`.

## 4. Данные для кабинета Yandex 360 (SSO)

В Keycloak (реалм ya360) → **Realm settings → General → Endpoints → SAML 2.0 Identity Provider Metadata**  
или URL:

```text
https://sso.nemero.online/realms/ya360/protocol/saml/descriptor
```

| Поле в Yandex 360 | Откуда взять |
| --- | --- |
| Login page URL | `Location` в metadata (SingleSignOnService) |
| Identity provider publisher | `entityID` = `https://sso.nemero.online/realms/ya360` |
| Verification certificate | `X509Certificate` из metadata (или Realm settings → Keys → RS256 → Certificate) |

В Yandex 360 for Business: **Общие настройки → Единый вход (SSO)** — вставить три значения выше.

Ожидаемые SAML Attribute Name (уже в клиенте):

- `User.EmailAddress` ← email  
- `User.Firstname` ← firstName  
- `User.Surname` ← lastName  
- NameID = email  

## 5. Проверка

1. Пользователь с email домена 360 есть в реалме ya360.  
2. SSO в кабинете 360 включён.  
3. Выйти из Яндекса → войти через SSO организации → редирект на Keycloak `ya360` → после пароля обратно в 360.

Типичные ошибки 360: неверные имена атрибутов, домен email не совпадает с доменом организации, просрочен/не тот signing certificate.
